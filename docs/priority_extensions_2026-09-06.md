# v4 이후 확장 우선순위와 실행 계약

실행 완료: 계산 보조 비교 32개 경로와 정합회로 파일럿 8개를 완료했다.
결과와 한계는 [확장 결과](priority_extensions_results.md)에 기록했다.

현재 제출용 원고는 전체 내용을 유지한 [3쪽 PDF](../submission/ACK2026_2026-09-07_pdf/README.md)다.
기존 결과표 5개와 주 실험 교차표를 포함하며, 기준 측정·보류 결과는 보조 탐색이다.
3쪽 확인은 고정 PDF 기준이다. 편집용 글꼴 정렬 DOCX는 Apple Pages에서 4쪽으로 표시된다.
추가 기여가 없었던 16회 재검사의 상세는 별도 결과 기록에 보존한다.
2026-09-07의 [완결성 재평가](paper_completeness_review_2026-09-07.md)에 따라 새 진단 방법·측정 선택
실험은 착수하지 않는다. 아래는 지금까지의 실행 이력이며 새로운 실행 지시가 아니다.

v4의 동일 최대 호출 예산 비교는 무피드백 33/36, 피드백 31/36으로 복구율 향상을
보이지 않았다. 첫 성공률도 28/36으로 같았다. 이 결과는 현재 원고의 표 5와 결론에
반영하며, 이전 46/48 주 결과의 분모에 합산하지 않는다.

## 1. 공진값 계산 보조

v4의 수치 선택 실패를 근거로 계산 보조를 먼저 검토한다. 새 중심주파수
97/127/157/193 MHz, 대역폭 비율 11/13/15/17%의 4개 설계에서 고장 8개를 생성했다.
각 사례 2회 반복 × 일반 피드백/계산 보조 피드백의 2조건으로 32개 경로다.
모델은 기존과 같은 gpt-5.6-luna low, 출력 상한 2000토큰, 최대 3회 호출이며
API 총상한은 96회다. 두 조건의 차이는 계산 결과를 입력에 포함하는지뿐이다.

계산기는 관측 netlist의 직렬/병렬 LC 쌍을 연결 관계로 찾고
f=1/(2π√LC), L=1/((2πf)²C), C=1/((2πf)²L)를 적용한다. 각 쌍의 현재 공진점,
목표 주파수의 리액턴스와 두 one-edit 후보를 제공한다. 정상 netlist·정답 부품·
정상값 목록을 읽지 않는다. 이는 **계산된 후보 정보를 제공하는 방법**이며 동적인
LLM tool calling이나 정답 보장이 아니다. 후보가 기능 복구를 보장하지 않는다고
두 조건의 같은 prompt에 명시한다. 실패 시에는 각 조건 모두 측정 피드백을 받는다.
각 후보는 초기 고장 회로에 one-edit로 적용하며, 이전 수정 위에 누적하지 않는다.

LLM의 필요성도 점검하기 위해 같은 계산만 쓰는 결정적 기준선을 둔다. 공진 오차가
큰 LC 쌍부터 정렬하고 부품명 순서로 최대 3개 후보를 검증해 성공 시 종료한다.
이 순서에는 고장 manifest나 정답 판정 결과를 사용하지 않는다. 기준선은 반복성이
없는 코드이므로 사례별 1회 수행하며, LLM의 반복 분모와 합산하지 않는다.

8개 모두 정상 PASS·고장 FAIL·정답 복구 PASS의 사전 검사를 통과했다. 결정적
기준선도 8/8을 복구했다. 이 결과는 숨기지 않으며, 계산 보조 LLM이 잘 동작해도
이 좁은 회로 집합에서 LLM이 필수임을 입증하는 것은 아니다. 설계는 v4를 본 뒤
정한 탐색적 확장이고, v5의 LLM 결과를 보고 사례나 prompt를 다시 바꾸지 않는다.

입력과 코드의 고정 계약: `experiments/calculator_v5.json`.
원시 사전 검증과 결정적 기준선: `build/calculator_v5_prescreen/`.

## 2. L형 정합회로 전이 파일럿

대역통과 필터 외 topology를 처음 확인한다. 50 Ω source와 100/150/200/250 Ω
load를 고정한 직렬 L·병렬 C의 L형 회로 4개를 91/131/181/223 MHz에 설계했다.
L/C 값 고장 8개를 각 1회 one-shot으로 평가한다. API 상한 8회이며 이 실험에는
피드백 비교나 공진 계산 보조를 넣지 않는다. 따라서 다른 회로의 절차 작동 확인용
파일럿이지 성능 일반화, 피드백 효과 또는 v5와의 순위 비교가 아니다.

Q=√(Rload/Rsource−1), L=Q·Rsource/(2πf), C=Q/(2πf·Rload)의 이상적
정합식을 사용했다. [Analog Devices 기술자료](https://www.analog.com/en/resources/technical-articles/radio-frequency-impedance-matching-calculations-and-simulations.html).
RF port의 z0는 실제 source/load termination으로 고정하고 Agent가 바꾸지 못하게
한다. 포트마다 정해진 기준의 native ngspice S-parameter로 평가한다. 평가 항목은
중심에서 S11≤−20 dB와 S21≥−0.25 dB, 0.9f/1.1f에서 S11≤−12 dB와
S21≥−0.5 dB다. BPF의 중심 peak·저지대역 판정기를 재사용하지 않는다.

8개 모두 정상 PASS·고장 FAIL·정답 복구 PASS의 사전 검사를 통과했다.
입력과 코드의 고정 계약: `experiments/matching_v1.json`.
원시 사전 검증: `build/matching_v1_prescreen/`.

## 3. 후순위

추가 완료: ESR/Q·기생·부품 편차의 320조건 민감도 확인을 수행했다.
정상 PASS는 8/320이며 유한 Q 정상 PASS는 없었다. 기존 기준을 그대로 쓰는
비이상적 복구 비교에 앞서 손실을 반영한 정상 설계와 사전 성능 기준이 필요하다.
[전체 결과와 다음 순서](nonideal_screen_v1_results.md)를 따른다.

이후 손실 보상 정상 설계와 새 사양을 별도로 고정한 비교도 완료했다.
이상적 공진 5/8, 수치 탐색 8/8, 같은 후보 + LLM 16/16 복구였으나 LLM 진단은
8/16이었다. 모든 LLM 응답이 최상위 수치 후보를 그대로 골랐다.
[상세 결과](lossy_repair_v1_results.md)에 따라 다음 우선순위는 진단과 수정의 역할 분리다.

진단 전용 후보 공개 비교도 새 8고장에서 완료했다. 미공개/공개 조건의 진단 정답은
모두 0/16, 부품 보류는 각각 15/16·16/16, 위치 오진은 1/16·0/16이었다.
공통 결정적 수정은 별도로 8/8 복구했다. 이 설정에서는 공개 시점만으로 진단이
개선되지 않았으므로, 다음에는 고장 전 기준 측정 등 원인을 구분할 증거를 정의한다.
[진단 비교 결과](diagnosis_visibility_v1_results.md)에 고정 조건과 검증을 기록했다.

고장 전 기준 측정 확장에서는 257 MHz 정상 설계가 정합 기준을 벗어나 v1 전체 계획을
API 0회에서 중단했다. 사전 검증을 통과한 3설계·6고장으로 별도 고정한 v2는 각 12회에서
기준 없음 3/12, 기준만 제공 3/12, 기준+역추정 12/12 진단 정답이었다.
기준만 제공한 조건은 오진 6회와 출력 한도 실패 2회를 포함한다. 같은 기준 측정으로
결정적 역추정도 6/6을 진단·복구해 LLM 추가 기여는 입증하지 못했다.
[기준 측정 비교 결과](reference_diagnosis_v2_results.md)에 사전 검증 후 부분집합 선택과
36 API 응답·30 native 재현의 감사 결과를 기록했다.
다음 우선순위는 API 반복 확대에 앞서 기준 측정 잡음·계측 drift·모델 불일치에 대한
결정적 역추정의 오진/보류 경계를 로컬에서 평가하는 것이다. 현재의 거의 무오차
합성 결과를 실계측 진단 성능으로 해석하지 않는다.

위 오차 민감도 확인도 완료했다. 105시나리오×9회로 상태의 945건 중 고장은
정답 190·보류 440·오진 0, 무고장 대조군은 보류 315·단일 부품 오경보 0이었다.
고장 최상위 가설은 모두 정답이었지만 기존 최선 잔차 문턱 때문에 보류가 늘었다.
잡음 σ=0.02 dB에서 33/60 진단했고, 0.05 dB부터 모두 보류했다. 시험한 최소
L/C drift ±0.1%와 손실·기생 모델 불일치 ±10%에서도 모두 보류했다.
[오차 민감도 결과](reference_robustness_v1_results.md)에 전체 격자와 native 69개 sweep의
독립 검증을 기록했다. 다음 우선순위는 별도 개발 집합에서 작은 고장·비균일 변화로
후보 순위와 잔차 분리를 확인한 뒤 보류 기준을 고정하고 미사용 설계로 검증하는 것이다.
현재 945건을 문턱 조정과 성능 검증에 동시에 사용하지 않는다.

작은 변화·비균일 오차 개발 확인도 새 4설계에서 완료했다. 주입 2,304건 중 최상위
후보가 틀린 385건은 모두 보류됐다. 기존 문턱의 최종 진단은 정답 509·보류 1,795·
오진 0, 무주입 대조군 오경보는 0/64였다. 기준 상태부터 규격 FAIL인 1설계도 사전
계획대로 포함한 진단 개발 집합이다. [결과와 보류 기준 설명](diagnosis_development_v1_results.md)에
최선 잔차 문턱만 완화하면 오진·오경보가 통과하는 반례를 기록했다.
다음에는 무고장 환경·모델 변화의 설명과 후보 간격을 포함한 규칙을 개발하고,
허용 오류 수준 아래에서 진단 비율을 높이도록 별도 보정 자료로 문턱을 정한 뒤
미사용 설계로 검증한다. 이번에는 기준을 변경하거나 최종 검증 성능을 주장하지 않았다.

이후 사용자 승인으로 다중 보류 기준을 구현·보정·적용했다. 개발과 분리한 보정 4설계에서
36개 후보 중 관찰 오진·오경보 0인 최다 정답 설정을 선택하고 미사용 4설계 전에 동결했다.
미사용 주입 2,304건의 정답은 기존 487→새 기준 615, 오진 0, 대조 오경보 0/64였다.
기존 정답 손실 없이 128건이 추가됐다. `scripts/diagnose_reference.py`의 기본 정책으로
연결했으며 [보정·평가 결과](abstention_calibration_v1_results.md)에 기준과 적용 범위를 기록했다.
추가 대조·안정성 조건의 개별 이점은 이번에 확인되지 않았고 큰 모델 오차의 진단도
개선되지 않았다. 후속 과제는 무고장 환경·모델 변화의 설명력과 측정 입력 불확실성이다.

추가 요청에 따라 확정 615건의 같은 ±0.01 dB 재검사를 4회에서 16회로 확대했다.
새 역추정 7,380회에서도 부품·방향 반전은 없었고 모두 16/16 일치했다.
[추가 재검사 결과](stability_extension_v1_results.md)에 사후 확인의 분모와 계산량을 기록했다.
이 범위에서 반복 수만 늘릴 추가 탐지 이점은 확인되지 않아 기본 4회는 유지한다.

RAG는 현재의 수치 실패를 직접 해결한다는 근거가 부족하고 별도 corpus 검증도
필요하므로 후순위다. LNA·복합 고장·실측은 이번 제출 범위를 크게 늘려 후속 연구로 둔다.

## 공통 기록 및 비용

기존 키 재사용 승인을 유지한다. 외부 API 입력은 새로 수식에서 생성한 합성 회로,
목표 수치, 계산 결과와 시뮬레이션 수치뿐이며 개인 정보나 논문 원문을 보내지 않는다.
요청을 먼저 기록하고 원본 API 응답, ID, usage, incomplete_details, 수정 회로,
시뮬레이터 출력을 보존한다. 자동 API 재시도는 없고 transport 오류는 전체 실행을
중단한다. 수정안이 실패해도 정답에 맞춰 교정하지 않는다.

최신 [공식 가격표](https://developers.openai.com/api/docs/models/gpt-5.6-luna)에는
cache write가 일반 입력의 1.25배라고 명시돼 있다. 새 집계에는 백만 토큰당
일반 input $0.20, cache write $0.25, cached input $0.02, output $1.20을 적용한다.
이전 v4의 추정 비용도 원시 usage를 보존한 채 cache write 할증을 따로 보정한다.
비용 보정은 복구 판정이나 고정 프로토콜을 변경하지 않는다.
