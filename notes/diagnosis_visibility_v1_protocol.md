# 수정 후보 공개 시점과 진단 비교: 사전 계약

2026-09-06. lossy_repair_v1에서 LLM이 수치 탐색 최상위 후보를 16/16회 그대로 선택하고
위치·방향 진단은 8/16이었던 관찰 뒤 정한 별도의 탐색 비교다. 이전 사례를 재사용하지 않는다.

## 질문

진단 시 수치 수정 후보를 함께 보여주는 것이 후보 없이 먼저 진단하는 것보다
실제 주입 고장의 위치·방향 정답률과 오진·판단 보류를 바꾸는가?
두 조건은 같은 진단 전용 지시문·schema를 쓰고 **수치 후보 필드 유무만 다르다**.
이전의 진단+수정 동시 출력과는 질문 형식도 바뀌므로 이전 8/16과 직접 인과 비교하지 않는다.

## 새 사례와 사전 검증

101/163/199/241 MHz, BW 16/18/20/22%, seed 202609080..202609083,
설계당 주 L/C ±2% 공차 벡터 1개. lossy_repair_v1의 보상 설계·고정 손실/기생값·사양을 그대로 쓴다.
각 설계의 사전 지정 2부품을 0.55배/1.8배로 바꾸는 8사례다. 모두 생성·보존하며
정상 PASS·고장 FAIL·원래 공차 포함 값으로 한 번 수정한 oracle PASS를 검증한다.
하나라도 부적격이면 사례/사양을 다시 골라 실행하지 않고 사전 검증 실패로 멈춘다.

수치 후보는 공개된 관측 회로만으로 앞서 고정한 ABCD 검색을 실행한다.
사례당 최대 354회 전방 모델 계산, 각 2001주파수이며 정상값/정답 위치는 입력하지 않는다.
미노출 조건의 요청에는 이 계산 결과나 그 요약을 넣지 않는다.

## 두 조건과 예산

- diagnose_before_candidates: 관측 회로·공개 모델·사양·최초 native metric만 보고 진단을 고정한다.
- diagnose_with_candidates: 위 입력에 같은 수치 탐색의 상위 3후보·예측 metric을 추가해 진단을 고정한다.

두 조건 각각 8사례×2회=16응답, **각 1회 호출**이다. gpt-5.6-luna low,
출력 상한 2000토큰, API 총상한 32회, 자동 재시도 0회, store=false다.
사례와 반복 인덱스로 조건 실행 순서를 교차한다. 각 요청은 독립된 새 입력이며
다른 조건의 응답이나 진단을 넘기지 않는다. 성공 조기 종료나 두 번째 진단은 없다.
미완료 응답·schema 실패도 계획 분모에 남긴다. transport 오류는 기록 후 전체 중단한다.

진단 후 수정은 양쪽 모두 동일한 결정적 최상위 수치 후보를 최초 고장 회로에 한 값 수정한다.
이를 사례당 1회 native SPICE로 검증해 양쪽의 공통 후속 단계로 사용한다.
이 수정은 진단 내용에 의존하지 않으므로 **조건별 복구율 차이를 검정하는 실험이 아니다**.
두 조건의 복구가 같더라도 진단 분리의 복구 우위라고 해석하지 않는다.
진단을 수정 성공 여부로 소급 교정하지 않는다.

## 판단 보류와 집계

모든 조건에서 component=unknown을 허용한다. 이때 방향도 unknown_direction이어야 한다.
부품을 특정하되 방향만 모르는 응답도 허용한다. 판단 보류는 정답으로 세지 않는다.
위치 정답, 위치+방향 정답, 잘못 특정한 위치, component=unknown,
방향 불명, API 실패를 계획 분모 16에 대해 각각 보고한다.
판단한 응답만의 정확도를 보조적으로 보되 coverage와 함께 제시한다.
수치 최상위 후보와 실제 고장이 다른 사례의 오진은 별도 표에 남긴다.

동일 사례·반복에 대한 두 조건의 정답 일치/불일치 표와 사례별 결과를 보고한다.
두 반복은 독립 회로가 아니며 8고장은 4설계에 묶인다. 작은 탐색 결과에 통계적 우위나
실제 부품 고장 진단 일반화를 주장하지 않는다. 더 좋아 보이는 조건에 맞춰 후속 반복을 추가하지 않는다.

## 보존과 검증

원본 API 응답·ID·usage·request/prompt hash·수치 탐색 입력과 결과를 보존한다.
입력 차이가 정확히 수치 후보 필드 하나인지 확인하고, 전체 진단을 원문에서 재집계한다.
정상/고장/oracle/공통 수정의 native SPICE 기록과 별도 nodal 계산을 재검증한다.
코드·manifest·이 계획은 `experiments/diagnosis_visibility_v1.json`에 hash로 고정한다.

사용자가 승인한 기존 API 키를 재사용한다. 외부로 보내는 자료는 수식 생성 합성 회로와
수치뿐이며 논문 원문이나 실제 사용자 회로는 보내지 않는다. 단가는 앞서 확인한
[OpenAI 공식 문서](https://developers.openai.com/api/docs/models/gpt-5.6-luna)의
input/cached/write/output 백만 토큰당 $0.20/$0.02/$0.25/$1.20를 추정에 사용한다.
